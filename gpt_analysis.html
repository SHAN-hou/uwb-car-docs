范围与关键结论

这不是一个单 MCU 工程，而是一个由 3 套嵌入式系统串起来的跟随控制链路: BU04 UWB 测量板 负责测量与输出， signal_board_c8t6 负责仲裁和避障， 根目录主工程负责最终电机闭环执行。

主控主板

STM32F103RC。负责 PWM/ADC/FOC 实时控制、功率保护、主循环调度，以及把 $FLW 帧转成速度/转向命令。

信号板

STM32F103C8T6。负责蓝牙启停门控、TOFSense 障碍物仲裁、BU04 跟随帧融合，然后重新生成新的 $FLW 给主板。

UWB 子系统

BU04 / Ai-UWB-SDK。负责 UWB 节点/标签启动、测距/PDoA 输出、AT 配置面和串口输出适配。

核心判断

  1. 当前工程已从通用 hoverboard/BBCAR 固件改造成“UWB 跟随 + 信号板避障叠加 + 电机闭环执行”的三层结构。
  2. signal_board_c8t6 不是透传板，而是决策仲裁层。它会把 UWB 原始测量改写成策略化的 $FLW 指令。
  3. 主控主板在 UWB 路径中主动清除了部分传统输入保护和 FOC 错误锁存，保留的核心硬保护主要剩下电流斩波、电池/温度断电和接收超时停车。
  4. BU04程序 与 Ai-UWB-SDK 的业务代码基本同构，前者主要多了文档/图片，后者多了 Arduino 示例和调试配置，不是两套不同算法分支。

2. 每个模块的具体职责、判断逻辑、性能指标

2.1 主控主板模块

模块 具体职责 判断逻辑 性能指标/状态
platformio.ini
Inc/config.h		 定义主板编译形态和运行边界，包括电机、电流、温度、电池、UWB 跟随参数。 编译期强制 VARIANT_BBCAR；UWB 跟随参数由宏固定，比如目标距离、迟滞、超时、最大速度/转向。 主板 64 MHz；-O2；PWM 频率 16000 Hz；A2BIT_CONV=50；FLW_TIMEOUT_MS=1000。
Src/main.c 执行系统初始化、主循环节拍控制、UWB 控制量注入、后级功率/温度/断电处理。 主循环以 buzzerTimer 节拍驱动；每次循环先维护输入与使能，再在 UWB 段执行: flw_check_timeout()， 清 timeoutFlgADC/Serial/Gen， 清左右电机 z_errCode， 强制 enable=1， 把 uart_steer_cmd/uart_speed_cmd 注入输入通道。 当两者同时为 0 时，主动清空滤波器和斜坡状态，避免残余滑行。 主循环目标间隔约 2 ms（DELAY_IN_MAIN_LOOP=2，1 ms 对应 16 个 ISR tick）。
Src/flw_follow.c 解析 $FLW,<dist_cm>,<angle_x10>,<x_cm>,<y_cm>,<status> 并生成主板所需的速度/转向命令。 status!=1 直接停车； dist<150 直接停车； 角度死区 30°； 150~165 cm 输出最小前进速度 80； 超出迟滞区后按 (dist-target-hyst)*3 + 80 增加速度，上限 100； 转向为 angle_deg*4，上限 ±350； 接收超时 1000 ms 清零。 ASCII 行缓冲 80 字节；解析成功才刷新最近接收时间；适合 DMA 分块喂入。
Src/util.c 这是主板最大的中间层，负责输入校准、类型识别、限幅、滤波、混合、串口 DMA 桥、EEPROM 参数装载、侧板 LED/传感器、BBCAR 模式逻辑。 bbcarDetectDrivingMode() 在启动时用踏板原始值判断模式 1~4； 若没有检测到有效踏板组合，则默认进入模式 1，等价于“无踏板，仅 UWB 跟随”。 usart3_rx_check() 基于 DMA 环形缓冲和 IDLE 中断分片调用 parse_uart_control()。 bbcarLoop() 仍保留，但当前主流程已绕过，不再是主命令源。 串口接收采用 DMA 环形缓冲；滤波、斜坡、混合都在主循环里执行；当前它更像“输入/安全/持久化/桥接总线层”，而不是简单工具库。
Src/control.c 采集 PPM/PWM/Nunchuk 人工输入，并维护通用超时计数和安全中位回退。 PPM/PWM 只接受 900~2100 us 脉宽并夹到 1000~2000 us； 超过 500 ms 无信号则回退到中位值 500。 Nunchuk 读失败、校验和全 0/全 FF、或通用超时超过阈值时，立即写入静止中位值并转入重连状态。 SysTick 1 kHz 维护超时；这一路在当前 UWB 跟随模式下保留代码，但控制权已大幅让位给串口 $FLW。
Src/bldc.c 作为实时控制 ISR，负责 ADC 偏置校准、电流采样、电压滤波、蜂鸣器、双电机控制器执行和 PWM 输出。 前 2000 个 DMA 中断只做 ADC 偏置校准； 若 ABS(cur_DC) > I_DC_MAX * A2BIT_CONV 或 enable==0，直接关闭对应 PWM 输出使能； 使用 OverrunFlag 防重入； 仅当 enable 且左右控制器都无错误时，enableFin 才传给控制器。 ADC DMA 中断频率约 16 kHz；PWM 分辨率 2000；每个中断都执行左右两路控制器。
Src/BLDC_controller.c
Src/BLDC_controller_data.c		 承载自动生成的双电机控制核，包括 FOC/SIN/COM 模式、相电流环、速度环、场弱、相位处理和输出调制。 根据输入的控制模式、霍尔、相电流、命令值和参数表计算每相 PWM 占空输出，以及错误码、转速等状态量。 被 bldc.c 在 16 kHz 中断里驱动；这是真正的实时控制内核。
Src/setup.c 构建外设拓扑: 双定时器三相 PWM、双 ADC 同步采样、UART DMA、ADC/DMA 中断、I2C 等。 USART2/3 RX 都配置成 DMA 环形模式，并启用 IDLE 中断； ADC1/ADC2 使用规则同步采样； 左右 PWM 定时器周期都按 64000000 / 2 / PWM_FREQ 计算。 主板系统时钟 64 MHz；USART2/3 均支持 DMA RX；ADC 和 PWM 对齐是整个实时控制性能的基础。
Src/comms.c 参数注册、命令注册、运行期监看、参数写入和 EEPROM 保存。 命令集包含 GET/HELP/WATCH/SET/INIT/SAVE； 用 command.semaphore 保证命令串行执行； 参数表绑定到控制参数、输入参数、运行变量、电池和温度等。 最多监看 15 个参数；当前在 UWB 跟随主链中属于调试/维护面，不是实时主路径。
Src/eeprom.c 以双页 Flash 模拟 EEPROM，保存主板参数。 根据 ERASED / RECEIVE_DATA / VALID_PAGE 三态修复页一致性； 页面写满后自动迁移； 初始化时能处理写入中断后的半完成状态。 典型双页轮转结构；把参数持久化风险从业务层剥离出去。
Src/stm32f1xx_it.c 连接中断到业务回调。 SysTick 转发到 PPM/PWM 超时维护； USART2/3 在检测到 IDLE 时分别调用 usart2_rx_check() / usart3_rx_check()； Cortex fault 进入无限循环，没有源码级自恢复逻辑。 负责把“中断事件”翻译成“数据可处理”信号；是 DMA 串口主链的一部分。
Src/pcf8574.c
Src/hd44780.c		 提供 I2C 字符显示外围。 不参与当前跟随、避障或电机执行决策。 外围 UI，性能要求低。

2.2 信号板模块

模块 具体职责 判断逻辑 性能指标/状态
signal_board_c8t6/src/main.c 作为仲裁层，接收蓝牙启停、缓存 BU04 $FLW、读取避障结果，并生成发给主板的最终 $FLW。 蓝牙行解析只承认 START/STOP； bt_armed==0 时无条件发送停车帧； 若避障动作是 SHIFT/ROTATE，则完全覆盖 UWB 帧； 若只是 SLOW_DOWN，只限制 dist，保留 UWB 角度； 若 UWB 超时，则发送停车帧。 72 MHz；USART1/2/3 全部 115200；CAN 1 Mbps；转发周期 50 ms（20 Hz）；UWB 新鲜度超时 500 ms；空闲时 __WFI()。

3. 系统架构

整体是“测量层 -> 仲裁层 -> 执行层”的三级结构，数据主线采用 $FLW 协议贯穿。 
[HC-04 / BU03 蓝牙 START/STOP]
              |
              v
      [Signal Board USART1]

[BU04 UWB 测量板] --$FLW/JSON--> [Signal Board USART2]
                                      |
[TOFSense 64 像素 CAN] -------------> [Signal Board 避障仲裁]
                                      |
                                      | 重新生成 $FLW
                                      v
                             [Motor Mainboard USART3 DMA]
                                      |
                                      v
                              [flw_follow.c 解析]
                                      |
                                      v
                          [main.c 注入 speed/steer]
                                      |
                                      v
                    [util.c 滤波/限幅/混合/配置总线层]
                                      |
                                      v
                   [bldc.c 16kHz ISR + BLDC_controller]
                                      |
                                      v
                            [TIM1/TIM8 PWM -> 双电机]

架构分层

  1. 测量层: BU04 输出距离、角度、坐标或 TWR JSON。
  2. 仲裁层: 信号板根据蓝牙门控和 TOF 避障把“测量”改写成“允许执行的运动意图”。
  3. 执行层: 主板把 $FLW 转成速度/转向，再由 FOC 实时闭环驱动电机。

数据契约

$FLW,dist_cm,angle_x10,x_cm,y_cm,status

  • dist_cm: 在 UWB 原始链路里是目标距离；进入信号板后，也可能被改写成“希望主板形成的速度包络”。
  • angle_x10: 目标角度；进入信号板后可能被直接替换成避障转向命令。
  • status: 0/1/2/3 分别对应太近停车、允许跟随、太远停车、目标丢失。
这个系统最关键的架构特征是: 主板已经不再把 UWB 帧当成纯感知数据，而是当成最高优先级的外部控制源之一。 信号板进一步把避障结果写进同一套 $FLW 字段，形成“感知与策略同帧承载”的结构。

4. 各个模块的配合时序

4.1 上电时序

  1. 主控主板启动，完成 HAL、时钟、GPIO、TIM、ADC、UART 初始化，随后执行 BLDC_Init()、输入初始化、ADC 启动和上电提示。
  2. 主板启动后执行模式检测。若踏板不在定义好的最小/最大组合，代码会落到默认模式 1，这实际上就是为“无踏板 + UWB 跟随”场景准备的入口。
  3. 信号板启动，配置 72 MHz 时钟、3 路 UART 和 1 路 CAN，蓝牙默认未 armed，LED 熄灭。
  4. UWB 板启动，读取 NVM 配置，按 workmode、role、twr_pdoa_mode 进入配置模式或测量模式。
  5. 一旦 UWB 测量开始，BU04 持续向信号板输出 $FLW 或 TWR JSON，再由信号板整理后发给主板。

4.2 运行闭环时序

  1. BU04 产生距离/角度/坐标结果，UWB 输出层把结果组装成 $FLW 帧或通过桥接层从 JSON 转成 $FLW。
  2. 信号板 USART2 字节流解析器缓存最近一帧 UWB 数据和时间戳。
  3. TOFSense 经 CAN 连续送来 64 个像素帧；信号板只有在收齐 64 个像素后，才刷新一次左/中/右三区结果。
  4. 信号板运行避障状态机，得出 NONE / SLOW_DOWN / SHIFT / ROTATE 之一。
  5. 每 50 ms，信号板按照“蓝牙门控 -> 避障覆盖 -> UWB 新鲜度 -> 停车”顺序发一帧新的 $FLW 给主板。
  6. 主板 USART3 通过 DMA 环形缓冲接收，IDLE 中断触发 usart3_rx_check()，再喂给 parse_uart_control()。
  7. flw_follow.c 解析完整行并更新 uart_speed_cmd / uart_steer_cmd。
  8. 主板主循环约每 2 ms 执行一次，把 UWB 命令注入输入通道、做滤波/斜坡/混合，并继续检查温度、电池和断电逻辑。
  9. bldc.c 在约 16 kHz 的 ADC DMA 中断中执行电流采样、硬电流保护、控制器求解和 PWM 更新。
  10. 如果任何高优先级保护触发，例如电流斩波、电池/温度断电、蓝牙未 armed 或主板接收超时，车辆进入停车或断电状态。

7. 优先级

7.1 控制权优先级

  1. 主板底层硬保护最高: 电流斩波、电池/温度断电一旦触发，直接压过一切上游命令。
  2. 信号板蓝牙门控次高: 未 armed 时，无论 UWB 和 TOF 给出什么，最终都是停车帧。
  3. 信号板硬避障高于 UWB 跟随: SHIFT/ROTATE 直接覆盖 UWB 距离和角度。
  4. 信号板减速策略高于纯 UWB: SLOW_DOWN 会限制距离包络，从而限制主板生成的速度。
  5. UWB 跟随高于本地主动输入: 主板当前主流程里，串口 $FLW 已经覆盖了原本的踏板控制权。
  6. 传统 ADC/PPM/PWM/通用超时保护已降级: 在 UWB 注入段被清零，不再是最终裁决者。

7.2 时间调度优先级

  1. DMA1_Channel1_IRQHandler 约 16 kHz，是真正最高频、最高实时性的执行层。
  2. 主板主循环约 2 ms 一次，负责把上游指令转成控制器输入。
  3. 信号板每 50 ms 输出一次新的决策帧，形成 20 Hz 的仲裁层。
  4. 信号板调试输出约 500 ms 一次，只用于观察。
  5. UWB 输出频率由底层测量栈决定；源码可见的工具阈值要求至少高于 5 Hz。

7.3 超时链路优先级

  • 信号板先用 500 ms 判断 BU04 掉线。
  • 主板再用 1000 ms 判断上游 $FLW 掉线。
  • 因此系统实际上是“双层超时停车”，且信号板先断，主板后兜底。

8. 信号板的深层逻辑

一句话结论: 信号板不是在“转发 UWB 数据”，而是在把 UWB 测量、蓝牙启停和 TOF 避障融合成一套新的、具有策略含义的 $FLW 控制语义。

8.1 它改变了 $FLW 的语义

  • 在 BU04 输出里，dist_cm 和 angle_x10 更接近“真实测量量”。
  • 进入信号板后，这两个字段会被改写成“想让主板产生怎样的速度和转向”。
  • 特别是 shift_dist=180、rotate_dist=130、slow_dist=200，并不是障碍物真实距离，而是发给主板的策略化距离值。
  • 因为主板的 flw_follow.c 是按 dist-target 算速度，所以信号板其实是在“借用距离字段远程调速”。

8.2 它做了显式的坐标系/增益变换

  • 普通跟随时，信号板不是原样转发角度，而是输出 angle = -uwb_angle_x10 * 5。
  • 这说明信号板同时做了符号翻转和5 倍增益放大，用来适配主板那一套转向控制尺度。
  • 这不是被动中继，而是主动坐标/增益适配层。

8.3 它把避障动作编码成主板能理解的运动意图

信号板动作 发送给主板的方式 主板最终感知到的含义
AVOID_SHIFT_LEFT/RIGHT 直接覆盖 dist_cm 和 angle_x10，并发送 status=1 继续跟随，但目标角度和距离被替换成“绕障转向 + 仍然前进”。
AVOID_ROTATE_CW/CCW 同样直接覆盖距离和角度，发送 status=1 主板会把它当成合法跟随目标，执行脱困转向/极慢前进。
AVOID_SLOW_DOWN 保留 UWB 角度，只把 dist_cm 上限压到 slow_dist=200 主板继续朝目标转向，但速度被压低。
未 armed / UWB 超时 发送 $FLW,0,0,0,0,3 主板直接停车。

8.4 它有明显的方向偏置

  • 当 right + middle 危险时，动作是 左移。
  • 当 middle 单独危险时，动作仍然是 左移。
  • 当 right + left 同时危险时，代码仍然选择 左移。
  • 只有 left 单独危险，或 middle + left 危险时，才选择 右移。
这说明信号板状态机存在默认左优先的避障偏置，而不是完全对称的左右决策器。 换句话说，系统把“左侧”当成更常见、更优先的逃逸方向，除非左侧本身已经构成主要障碍。

8.5 三面围堵时的脱困逻辑不是停车，而是交替旋转

  • 若左/中/右三侧都进入危险距离，信号板不会停车等待，而是进入旋转脱困。
  • 它用 s_turn_flag 在 ROTATE_CCW 和 ROTATE_CW 之间交替，避免持续朝一侧死打方向。
  • 这说明它的设计目标不是“最保守停车”，而是“尽量不断链地脱困并继续跟随”。

8.6 它与主板参数存在强耦合

  • 主板目标距离是 150 cm，信号板减速距离设置为 200 cm。
  • 这不是随意的数值。如果 slow_dist 小于或等于主板目标距离，主板会把它解读成“过近停车”，而不是“减速跟随”。
  • 因此信号板的 180 / 130 / 200 等数值，本质上是根据主板下游控制律反推出来的策略编码值。

8.7 深层本质

UWB 原始目标位置
        -> 信号板缓存
        -> TOF 64 像素聚合为三区风险
        -> 蓝牙 armed 判断
        -> 风险状态机决定是否改写 dist/angle/status
        -> 发送“合成后的虚拟跟随目标”
        -> 主板按普通跟随逻辑执行

结果: 主板无法区分“这帧是目标真实位置”还是“信号板为了避障而伪造的目标位置”。

这就是信号板的最深层逻辑: 它把原始感知数据变成了策略化控制语义。 从系统设计角度看，信号板是整个工程里真正的“行为仲裁器”。

边界与不可见部分

  • Ai-UWB-SDK/Components/HAL/DW/twr_pdoa/lib/*.lib 是二进制库。能看到的是入口函数、输出字段和外围桥接代码，看不到内部测距滤波、PDoA 求解和鲁棒性策略。
  • Drivers/*、CMSIS/*、USB 基础库文件数量很大，但它们属于供应商基础设施，不承载本项目特有的跟随/避障决策，因此按模块族归类更有分析价值。
  • BU04程序 与 Ai-UWB-SDK 的业务代码主体一致；它更多是发布和交付形态，而不是另一套运行时架构。
如果后续要继续深入，最值得追的不是 HAL，而是两件事: 一是主板 UWB 注入段为什么要主动清掉若干保护标志； 二是信号板避障策略中“左优先偏置”和“用虚拟距离调速”的设计是否符合实际场地需求。
