⚠️ 一、执行逻辑风险分析

🔴 风险 1：UART3 阻塞发送导致主循环卡顿
static inline void uart3_send_str(const char *s)
{
    HAL_UART_Transmit(&huart3, (uint8_t *)s, (uint16_t)strlen(s), 50);
}

问题： HAL_UART_Transmit 阻塞式发送，timeout=50ms。正常 25B @115200 = ~2.2ms。但 UART3 硬件异常时阻塞整整 50ms，20Hz 周期被吃满。

调试输出更严重： uart1_send_str(dbg) 约 120B = ~10ms 阻塞。

解决方案： 改用 DMA 或中断发送，不阻塞主循环。

🟡 风险 2：CAN ISR 中做浮点运算
s_pixels[idx].dis = temp / 1000.0f;  // 在CAN中断回调中

STM32F103 无硬件 FPU，软件浮点除法约 3-5μs。CAN 1Mbps 帧间隔 ~100μs，占 5%。64帧收齐时区域计算 ~50μs。

结论： 不会卡死，但消耗中断时间。可将浮点转换延迟到主循环。

🟡 风险 3：volatile 变量组非原子访问
static volatile int flw_dist = 0;
static volatile int flw_angle_x10 = 0;  // ISR写, 主循环读

单变量 32 位对齐读写原子。但多变量不是！ 可能读到新帧的 flw_dist + 旧帧的 flw_angle_x10。

实际影响： 概率极低，但极端情况导致一帧数据错配 → 轻微抖动。

解决方案： 主循环关中断拷贝一组数据后清标志。

🟡 风险 4：围堵状态机逻辑缺陷
if (r_danger && m_danger && l_danger) {
    if (s_turn_flag == 0) {        // 只有第一次进 CCW
        r.action = AVOID_ROTATE_CCW;
        s_turn_flag = 1;
    } else {                        // 之后永远进 CW
        r.action = AVOID_ROTATE_CW;
        s_turn_flag = 2;
    }
}

结果： 车只 CCW 转一帧(50ms)，然后永远 CW 转。若 CW 方向也被堵，车在墙角持续撞。

解决方案： flag 在 0/1/2 间循环，或用时间窗口切换方向。

🟡 风险 5：TOFSense 64帧不完整时永远等待
if (s_rx_mask == 0xFFFFFFFFFFFFFFFFULL) {  // 必须64位全1
    // 才更新避障数据
}

丢一个 CAN 帧 → s_rx_mask 永远凑不齐 → 避障数据冻结。若冻结时正在避障 → 车持续执行避障动作。

解决方案： 200ms 未收齐 → 清 s_rx_mask → 退化为 AVOID_NONE。

🎯 三、决策优先级

[1] bt_armed == 0        → 直接停车（最高，硬门控）
         ↓ (armed)
[2] ROTATE / SHIFT       → 完全覆盖UWB，直接避障
         ↓ (无紧急避障)
[3] UWB在线 + SLOW_DOWN  → 保持UWB角度，限速
         ↓ (无减速)
[4] UWB在线 + NONE       → 正常跟随（角度取反×5）
         ↓ (UWB离线)
[5] UWB超时(>500ms)     → 停车

评价： ✅ 合理。安全性逐级递增：人为停止 > 避障 > 跟随 > 超时保护。

🏗️ 四、架构合理性评估

合理之处 ✅

方面评价
职责分离信号板决策、电机板执行、BU04 测量。各板单一职责。
安全分层信号板门控 + 电机板超时双重保护，任一链路断都停车。
通信选择UWB/BLE 用 UART（简单），TOF 用 CAN（高速多设备）。
避障覆盖跟随避障优先级 > 跟随，不因跟随需求撞障碍。
协议统一统一 $FLW 帧格式，简化电机板实现。

架构问题 ⚠️

问题 1：信号板是单点故障
BU04 ─┐
BLE  ─┼─→ [信号板] ─→ 电机板
TOF  ─┘

信号板死机 → 电机板 1000ms 后超时停车。安全有保障，可用性为零。

评价： 对此类小车可接受，冗余成本太高。

问题 2：单向通信无反馈

电机板无法告知信号板当前转速、堵转状态、电池电量。信号板盲发指令。

影响： 堵转时信号板不知道，继续发同一避障指令。

评价： 当前功能够用。需速度闭环时再加反馈。

问题 3：角度增益链分散
BU04 angle_x10 → 信号板(取反×5) → 电机板(÷10 × KP=4)
等效增益: angle_raw × (-2)

两端都做增益，调参难以直观理解。建议集中到一处。

📋 六、结论

✅ 架构层面

整体合理，四板分工清晰，安全链完整（门控→避障→超时三重保护）。适合当前功能复杂度。

⚠️ 执行层面

主要薄弱点在阻塞 UART、TOF 无超时、围堵状态机。优先修复这三项可显著提升鲁棒性。

最需优先修复： ①UART3→DMA ②TOF超时重置 ③围堵状态机
