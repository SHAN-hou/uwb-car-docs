信号板完整数据流

从传感器原始数据 → 决策仲裁 → 发出电机驱动帧的每一步

阶段一 · 传感器数据接收（中断层，异步并行）
1 蓝牙接收 · USART1 中断

优先级=1 · PA10 RX · 115200 baud

每收1字节 → USART1_IRQHandler → bt_feed_byte()

按行拼装到 bt_line[16]，遇 \n 检查是否为 "START" 或 "STOP"

收到 "START\n" → bt_armed = 1, LED亮, 回复 "ACK_START\r\n"
收到 "STOP\n"  → bt_armed = 0, LED灭, 回复 "ACK_STOP\r\n"
其他内容       → 丢弃（bt_idx=0 重置）
缓冲区满(16字节) → bt_idx=0 丢弃当前行
2 UWB接收 · USART2 中断

优先级=1 · PA3 RX · 115200 baud

每收1字节 → USART2_IRQHandler → flw_feed_byte()

按行拼装到 flw_line[128]，遇 \n 检查是否为 $FLW, 开头

解析: sscanf(flw_line, "$FLW,%d,%d,%d,%d,%d", &d, &a, &x, &y, &s)
成功(==5) → 写入缓存变量:
   flw_dist      = d        (距离 cm)
   flw_angle_x10 = a        (角度×10)
   flw_x         = x        (X坐标 cm)
   flw_y         = y        (Y坐标 cm)
   flw_status    = s        (1=跟随 3=丢失)
   flw_have      = 1        (标记有数据)
   flw_last_ms   = HAL_GetTick()  (时间戳)
失败 → 保持旧数据，不更新时间戳（超时机制兜底）
3 TOF激光接收 · CAN1 中断

优先级=2 · PA11 RX · 1Mbps · StdID 0x200~0x2FF

每收1帧 → USB_LP_CAN1_RX0_IRQHandler → HAL_CAN_RxFifo0MsgPendingCallback → parse_pixel()

① 校验: StdID 范围 [0x200,0x2FF] + DLC≥7 + idx<64
② 解码: 8字节 → 距离(float m) + 状态(uint8) + 信号强度(uint16)
③ 存入: s_pixels[idx] = {dis, dis_status, signal_strength}
④ 位图: s_rx_mask |= (1ULL << idx)
⑤ 判满: if (s_rx_mask == 0xFFFF_FFFF_FFFF_FFFF)
   → 遍历3个区各16像素，取每区最小有效距离(status==0)
   → 写入 s_zone = {left/middle/right 的 dis, rssi, status}
   → s_zone_ready = true
   → s_rx_mask = 0 (开始下一帧)
⚠ 关键：三路中断完全独立
  • USART1(蓝牙)写 bt_armed
  • USART2(UWB)写 flw_* 系列变量
  • CAN1(TOF)写 s_zone
  • 三者之间没有任何共享资源，不会互相阻塞
阶段二 · 决策仲裁（主循环轮询，每50ms一次）
4 读取TOF避障结果

主循环每圈执行：

if (tofsense_get_zones(&zone)) {
    // zone有新数据 → 重新做避障决策
    oa_result = tofsense_avoid_danger(&zone, &avoid_cfg);
}
// 否则 → oa_result 保持上次的值

tofsense_get_zones 内部会 __disable_irq() 原子拷贝zone，然后清 s_zone_ready

5 避障决策树（7路分支）

输入：左/中/右三区的 距离 + 信号强度 + 状态

有效性过滤: rssi > 阈值(2) 且 status ≠ 255 → 该区"有效"
危险判定: 有效 且 距离 < 0.6m → 该区"危险"

决策表（按优先级从高到低）:
┌─────────────┬──────────┬───────────────────────────┐
│ 条件         │ 动作      │ 输出 (steer_x10, dist_cm) │
├─────────────┼──────────┼───────────────────────────┤
│ R+M+L 危险   │ 围堵脱困  │ ±1500, 130 (交替CCW/CW)   │
│ R+M 危险     │ 左闪      │ -1100, 180                │
│ M+L 危险     │ 右闪      │ +1100, 180                │
│ R+L 危险     │ 左闪      │ -1100, 180                │
│ 仅R 危险     │ 左闪      │ -1100, 180                │
│ 仅M 危险     │ 左闪      │ -1100, 180                │
│ 仅L 危险     │ 右闪      │ +1100, 180                │
│ 无危险但<1m  │ 减速      │ dist限到200               │
│ 完全无障碍    │ 无动作    │ —                         │
└─────────────┴──────────┴───────────────────────────┘
6 50ms周期发送触发

检查: (int32_t)(now - next_tx) >= 0

满足 → 进入仲裁分支；不满足 → __WFI() 睡眠等下一轮

阶段三 · 帧生成与发送（决策出口，互斥4选1）
7 四路互斥决策（if-else if 结构） 
分支A: if (!bt_armed)
  └─ 直接发: "$FLW,0,0,0,0,3\r\n" (停车帧, status=3)

分支B: else if (避障动作 ∈ {SHIFT_LEFT/RIGHT, ROTATE_CW/CCW})
  └─ 完全覆盖UWB数据
  └─ 发: "$FLW,{oa.dist_cm},{oa.steer_x10},0,0,1\r\n"
  └─ 示例: "$FLW,180,-1100,0,0,1\r\n" (左闪)

分支C: else if (flw_have && 未超时500ms)
  └─ 调用 build_avoid_frame() 融合 UWB + TOF减速
  └─ 内部逻辑:
     │ angle = -uwb_angle_x10 * 5  ← ⚠ 取反+5倍增益
     │ if SLOW_DOWN: dist = min(uwb_dist, 200)
     │ if NONE: dist = uwb_dist, angle不变
  └─ 发: "$FLW,{dist},{angle},0,0,1\r\n"
  └─ 示例: UWB报 dist=300,angle=150 → "$FLW,300,-750,0,0,1\r\n"

分支D: else
  └─ UWB超时或从未收到数据
  └─ 直接发: "$FLW,0,0,0,0,3\r\n" (停车帧)
8 UART3 物理发送

uart3_send_str(frame) → HAL_UART_Transmit(&huart3, ..., 50)

115200 baud 发30字节约 2.6ms，正常情况远小于50ms超时

发送完成后主循环继续下一轮

阶段四 · 调试回传（每500ms，非关键路径）
9 蓝牙调试输出

每500ms通过USART1回传给手机/BU03：

TOF:L0.85 M1.20 R0.43 [R>] d:180 s:1100 | UWB:Y d=300 a=150 age=45

包含：三区距离、当前避障动作、UWB状态、数据年龄

死区判断电机板|angle| < 30 → 0-75 (不在死区)

⚠ BUG就在这里

UWB说目标在右边(+15°) → 经过信号板 -angle×5 变成 -750 → 电机板算出 steer=-300 → 混控右轮快左轮慢 → 车向左转！

车应该向右追目标，实际向左跑，越走越远。

修复：去掉负号，改为 angle = uwb_angle_x10 * 5

异常场景数据流

场景1：BU04 UWB掉线

USART2中断停止 → flw_last_ms 不再更新
主循环: (now - flw_last_ms) > 500ms → 走分支D
→ 每50ms发 "$FLW,0,0,0,0,3\r\n"
→ 电机板 flw_apply 见 status=3 → speed=0, steer=0 → 停车

场景2：TOF CAN丢帧

64帧只收到63帧 → s_rx_mask ≠ 全1 → s_zone_ready 永远false
→ tofsense_get_zones() 永远返回false
→ oa_result 冻结在丢帧前的值
→ 如果是AVOID_NONE → UWB正常走，只是没有避障保护
→ 如果是SHIFT_LEFT → 会一直左闪！直到下次收齐64帧

场景3：按STOP后再START

STOP → bt_armed=0 → 持续发停车帧
START → bt_armed=1
   ├─ 如果BU04一直在发 → flw_have=1, flw_last_ms是最近的 → 立即恢复跟随
   └─ 如果BU04也断开了(BU03 STOP同时断UWB)
      → flw_last_ms 是旧时间 → 超时 → 继续发停车帧
      → 必须等BU04重新发出$FLW帧才能恢复
      → 这就是你反馈的"问题④"的原因

场景4：三路同时有数据

中断层: USART1/USART2/CAN1 各自独立更新缓存（不冲突）
主循环50ms触发:
  ① 读zone → 算oa_result
  ② 进入if-else:
     bt_armed=1 + oa_result=SHIFT_LEFT → 走分支B（避障覆盖UWB）
     UWB数据完全忽略，不会"打架"

总结：决策逻辑清晰度评价

✓ 做得好的地方
  • 中断层完全解耦：三路传感器各写各的变量，零冲突
  • 决策层互斥分支：永远只走一条路，不会叠加
  • 时间基准可靠：(int32_t)(now-next_tx)>=0 抗回卷
  • 超时兜底完善：UWB 500ms + 电机板 1000ms 双重保护
✗ 存在的问题
  • 角度取反bug：-uwb_angle_x10 * 5 导致转向方向完全反
  • TOF无超时：丢1帧CAN就冻结避障数据，可能一直执行旧的避障动作
  • STOP后UWB恢复依赖BU04：信号板不主动请求BU04重连
  • sscanf在ISR中：flw_feed_byte 在USART2中断里调用 sscanf，耗时约20-50μs
