整车代码全景分析 · V1.0

STM32F103 FOC UWB Follow TOFSense Obstacle Avoidance CAN 1Mbps

代码分两块 MCU：主控板（STM32F103RC，Src/ + Inc/） 跑 FOC 双电机 + UWB 跟随； 信号板（STM32F103C8T6，signal_board_c8t6/src/） 跑蓝牙门控 + UWB 解析 + TOFSense 避障融合。 两板通过 USART3 串口以 $FLW,d,a,x,y,s\r\n 帧通信。

一、模块功能综述

主控板（V1.0/Src）

main.c

主状态机、主循环、电源/温度/电压/超时仲裁、命令融合到 PWM。

bldc.c

16 kHz DMA 中断里跑 FOC（调用 Simulink 生成代码），含相电流采样、过流斩波、霍尔读取、蜂鸣方波。

BLDC_controller.*

Matlab/Simulink 自动生成的 FOC 控制器（COM/SIN/FOC 三模式、转矩/速度/电压三模式）。

setup.c

HAL 外设初始化（TIM1/8 PWM、双 ADC 注入扫描、USART2/3 DMA+IDLE、I2C2、GPIO）。

util.c

输入抽象层、readCommand、低通/限速滤波、混控器、巡航/驻车/电制动/多击检测、DMA 环形缓冲、串口调试协议、poweroff。

control.c

PPM 解码（EXTI+TIM2）、PWM 双通道解码、Nunchuk I²C 状态机。

comms.c

调试串口的命令解析器（参数读写、watch list、错误码）。

eeprom.c

FLASH 模拟 EEPROM，持久化用户/控制参数。

flw_follow.c

解析下行 $FLW 帧，按距离/角度做 P 控；含死区、滞回、超时停车。

hd44780.c / pcf8574.c

I²C 1602 LCD 驱动。

stm32f1xx_it.c

所有 ISR 入口（SysTick、DMA、USART、EXTI）。

Inc/config.h, defines.h

全部宏开关（变体、引脚映射、保护阈值、滤波系数）。

信号板（signal_board_c8t6/src）

main.c

三路 UART + CAN 初始化；蓝牙 START/STOP 状态机 bt_armed；BU04 $FLW 缓存；50 ms 周期向主控板转发；融合避障决策。

tofsense_can.c/.h

TOFSense-M CAN 协议解析（64 像素拼帧→左/中/右三区最小距离），三区危险/减速判别状态机。

电源/外设：OFF_PORT/PIN 软自锁；BUTTON_PIN 长按调用 poweroff() 写 EEPROM 并放掉锁存。

四、配合时序

  1. 上电：主控板 HAL_Init → SystemClock → MX_GPIO/TIM/ADC → BLDC_Init → 自锁 → Input_Lim_Init/Input_Init → ADC_Start → poweronMelody；信号板 SystemClock 72MHz → UART1/2/3 + CAN1 + tofsense_can_init → 心跳 LED。
  2. 稳态（每 50 ms）：信号板把最新仲裁帧推给主控板；主控板 usart3_rx_check（IDLE 触发）调 parse_uart_control 拆 \n 行 → flw_apply 写 uart_*_cmd。
  3. 主控板主循环：readCommand→清零→（覆盖为 uart_*_cmd）→ rate→LP→mixer→pwml/pwmr。
  4. 16 kHz FOC：DMA 中断把 pwml/pwmr 喂入 rtU_*.r_inpTgt，跑 FOC 写 PWM。
  5. 关机：长按按键→poweroffPressCheck→poweroff → 释放 OFF_PIN。

五、保护机制

  • 过流 L1：BLDC_controller 内 i_max 限幅。
  • 过流 L2（硬斩波）：bldc.c 中 |curL/R_DC| > I_DC_MAX*A2BIT_CONV → 清 TIM_BDTR_MOE 立即关三相。
  • 过温：board_temp_deg_c ≥ TEMP_POWEROFF && speedAvgAbs<20 → poweroff()；≥TEMP_WARNING 5 哔。
  • 欠压：<BAT_DEAD && speedAvgAbs<20 关机；BAT_LVL1/LVL2 哔。
  • FOC 错误：rtY_*.z_errCode → 主循环 enable=0 + 1 哔。
  • 超时：timeoutFlgADC / timeoutFlgSerial / timeoutFlgGen 任一 → 蜂鸣 + 不更新命令；flw_check_timeout 1 s 无帧硬清零。
  • 启动安全：enable=0 时要求初始命令 |cmd|<50 才会自动 enable=1。
  • PWM 边界：pwm_margin=110 保证电流采样窗口。
  • OverrunFlag：阻止 FOC 中断重入。
  • CAN AutoBusOff + AutoRetransmission：信号板 CAN 总线故障自恢复。
  • 蓝牙门控：bt_armed=0 信号板强制下发停车帧 $FLW,0,0,0,0,3。
  • 避障兜底：三面围堵 ROTATE 交替方向，防止反复同方向卡死。
  • TOFSense 有效性：rssi>thr && status!=255 才参与判障。
  • 64 像素位图：必须全部收齐才更新区域，防止半帧脏数据。
  • 无活动停机：inactivity_timeout_counter 超过 INACTIVITY_TIMEOUT 分钟自动 poweroff()。

六、异常处理方式

  • Hard/Mem/Bus/Usage Fault：stm32f1xx_it.c 全部 while(1)（等看门狗复位/手动断电）。
  • UART ORE：信号板 __HAL_UART_CLEAR_OREFLAG + 读 DR；主控板由 HAL 处理。
  • 行缓冲溢出：flw_line / bt_line 超长 → idx=0 丢弃当前行。
  • sscanf 失败：返回 0，保持上一帧数据 + 不更新 flw_last_ms，被超时机制兜底。
  • I²C Nunchuk 失败：3 次重试 → NUNCHUK_RECONNECTING → 还原中点 + 置超时标志。
  • PPM/PWM 越界：丢弃该周期，ppm_valid=false；500 ms 无脉冲恢复中点。
  • ADC 范围错：readCommand 置 timeoutFlgADC，主循环禁能。
  • FOC z_errCode：enableFin = enable && !errCode 保证一旦出错电机零占空。
  • CAN 接收异常：HAL_CAN_GetRxMessage != HAL_OK 或 DLC<7 直接返回；标准 ID 之外被过滤器拦截。
  • EEPROM 写错误：HAL FLASH 状态返回上层；上电默认值兜底。

七、优先级

NVIC 抢占组 NVIC_PRIORITYGROUP_4（4 位抢占，0 位次优先级）。数值越小越高。

IRQPre说明
DMA1_Channel1 (FOC 16 kHz)0主控板最重要——电机控制实时性
EXTI2/3/15_10（PPM/PWM 捕获）0时间敏感的脉宽测量
USART2/3_IRQn + DMA1_Ch2/3/6/70同级，靠 IDLE 唤醒解析
信号板 USART1/21比 CAN 优先（保 BT/UWB 时序）
信号板 USB_LP_CAN1_RX0264 帧拼装可容忍延迟
SysTick0HAL_IncTick + PPM/PWM 软定时

应用层优先级（主循环判定顺序，越靠前越高）：

  1. 信号板：!bt_armed 停车 → 闪避/围堵 → 正常 UWB 跟随 → UWB 超时停车。
  2. 主控板：TEMP_POWEROFF / BAT_DEAD → z_errCode → timeoutFlgADC → timeoutFlgSerial → timeoutFlgGen → TEMP_WARNING → BAT_LVL1/2 → 倒车蜂鸣。
  3. UWB 控制段在 readCommand 之后直接覆盖所有 ADC/Serial 超时标志和 errCode，把跟随命令置为最高数据源。
  4. FOC 内 enableFin = enable && !errCode —— 硬件级最终一票否决。

八、信号板深层逻辑

1. 三层仲裁（每 50 ms 一次）

  • 第一层 蓝牙门控：bt_armed==0 直接发 $FLW,0,0,0,0,3（status=3=lost），主控端 flw_apply 见 status!=1 → 命令清零。物理急停通道。
  • 第二层 避障覆盖：oa_result.action ∈ {SHIFT_LEFT/RIGHT, ROTATE_CW/CCW} 时，完全抛弃 UWB 数据，用 (dist_cm, steer_x10) 自定帧；闪避 shift_steer=1100/dist=180，围堵 rotate_steer=1500/dist=130。
  • 第三层 跟随融合：build_avoid_frame 中 angle = -uwb_angle_x10 * 5（反向×5 增益，差速车需更大转向修正横向偏差）；SLOW_DOWN 时把上传的 dist 钳位到 slow_dist=200，让主控 P 控 speed=(dist-150)*KP 自然降速。

2. 避障决策树设计哲学

  • 把 8×8 TOF 像素简化到三扇区最小距离——保留最危险障碍信息，丢弃细节，决策稳定。
  • 多区同时报警优先选单侧最大空隙方向避让；左右对称报警时默认左闪消除二义性。
  • 三面围堵 s_turn_flag 让连续围堵帧交替输出 CCW/CW，避免锁死贴墙。
  • signal_strength_thr=2 & status!=255 过滤空气/玻璃误检触发的幻觉避障。

3. CAN 64 像素位图凑齐机制

  • s_rx_mask 用 64-bit 位图保证完整一帧才发布，避免拼帧中部分像素求最小导致漏检。
  • 凑齐后 s_rx_mask=0 自动开始下一帧。

4. 协议复用

信号板对主控板永远只用 $FLW。避障语义被"翻译"成 UWB 跟随语义（虚拟目标点），主控板 flw_follow.c 无需任何改动，保持解耦。status=1=跟随，status=3=停车。

5. 节能 + 抗抖

主循环 __WFI 睡眠，RX/CAN/SysTick 中断唤醒；50 ms 节拍 (int32_t)(now-next_tx)>=0 + next_tx += FORWARD_PERIOD_MS 是抗时钟回卷的标准 tick 算法，长运行无累积漂移。

6. LED 双重含义

PC13 上电 6 次心跳验证 GPIO 正常；之后常亮=已布防、灭=未布防——同时承担运行状态指示和电源/固件健康指示。

7. 调试串口回写

通过 USART1（蓝牙）把三区距离 + 决策动作 + UWB 状态实时广播给手机/BU03，现场无线调参不需重插线。

九、各模块明显漏洞

主控板

  1. 【致命】main.c UWB 段强制清零所有保护标志 + errCode + 强制 enable=1（main.c:336-341）： 
    timeoutFlgADC=0; timeoutFlgSerial=0; timeoutFlgGen=0;
rtY_Left.z_errCode=0; rtY_Right.z_errCode=0;
enable = 1;
    把过流、超时、FOC 错误码、电机使能逻辑全部短路。bldc.c::enableFin = enable && !errCode 两侧都被强制 true，硬件级一票否决形同虚设。
  2. 【严重】main.c:271-272 在 readCommand() 之后立刻 input1/2[inIdx].cmd = 0：所有 ADC/PPM/PWM/Serial/Nunchuk 输入实际被废弃；信号板掉线则没有备份控制源。
  3. flw_follow.c::uart_steer_cmd / uart_speed_cmd 未声明 volatile：主循环异步读、ISR 上下文异步写，编译器可能优化掉读取。
  4. bldc.c::OverrunFlag 顺序异常：if(OverrunFlag) return; 之前没 lock，return 时也不清标志；依赖单核 ISR 不会真嵌套才幸运不出问题。
  5. bldc.c 偏置标定 offsetcount<2000 阶段 return：要求电机绝对静止，未做强制刹车，外力转动会污染零位标定。
  6. HardFault/MemManage/BusFault/UsageFault_Handler 全是 while(1) 死循环且未开看门狗，故障后只能拔电源。
  7. eeprom.c 关机写 FLASH 没有 CRC/双副本，掉电中断写入会留下损坏参数。
  8. Nunchuk_Read 在主循环里 HAL_Delay(3)：阻塞调用破坏主循环节拍。
  9. flw_apply 没对 angle_x10 范围做检查：BU04 发极值时计算可读性差。
  10. USART2/3 与 DMA + DMA1_Channel1(FOC) 同为优先级 0：USART/DMA ISR 一旦执行 > 62.5 µs 就会丢一个 FOC 周期。

信号板

  1. 【严重】tofsense_can.c::s_rx_mask 必须 64 个像素全齐才发布：偶尔丢一两个像素时 s_rx_mask 永远凑不齐 0xFFFFFFFFFFFFFFFF，避障决策卡死在旧值；缺乏"换轮触发"或超时强制发布机制。
  2. flw_dist / flw_angle_x10 / flw_x / flw_y / flw_status 是分立 volatile：USART2 中断分多次写入，主循环 snprintf 可能读到一半新一半旧。
  3. build_avoid_frame 中 angle = -uwb_angle_x10 * 5：可达 5 位以上；主控 sscanf("%d") 后强转 (int16_t)，> ±32767 会截断翻转，瞬间出现反向大转向命令。
  4. tofsense_avoid_danger 中 r_danger && l_danger（无 m_danger）默认左闪：左右两侧障碍但正前方空旷应直行通过，目前会无谓转向，可能撞上左侧障碍。
  5. avoid_cfg.slow_dist=200 必须 > 电机板 TARGET=150 是软约束，无运行时校验。
  6. bt_armed volatile 但 LED 切换不在临界区（仅显示错位）。
  7. RX 缓存 bt_line/flw_line（16/128）溢出策略是丢整行——攻击者持续无 \n 数据可永久阻断该串口合法命令。
  8. 信号板没有任何独立看门狗（IWDG/WWDG 未启用）：主循环卡死时下游靠 1 s FLW 超时兜底——存在最长 1 s 失控窗口。

十、模块间配合时的问题

  1. 【最优先】UWB 段对保护机制的"重置"在 200 Hz 频率上持续冲刷错误标志：bldc.c 16 kHz 中刚检测到的 z_errCode，5 ms 内被主循环擦除。错误蜂鸣 if (rtY_Left.z_errCode) beepCount(1,24,1) 永远进不去 → 故障静默。
  2. 频率失配：信号板 20 Hz vs 主控 200 Hz vs FOC 16 kHz。一次避障决策最迟 50+5 ≈ 55 ms 才传达到电机；以 1 m/s 速度计 ≈ 5.5 cm 盲走距离。
  3. 64 像素拼帧失败 × 50 ms 强制发帧：信号板避障数据卡死时仍每 50 ms 发"旧"判决；主控按其驱动电机。
  4. status=1 复用语义混淆：信号板把"虚拟跟随点"塞进 $FLW,...,1，主控无法区分真实 UWB 数据和避障命令。
  5. USART3 单向通信：主控只读不应答，信号板无法知道电机板是否真正执行了避障。
  6. FLW_TIMEOUT_MS=1000 vs 信号板 50 ms 推帧：信号板掉电/卡死 → 主控需 1 s 才停车；期间车辆失控。
  7. UWB 段覆盖 vs readCommand：timeoutFlgADC=1 立即被 UWB 段重置；调试串口看到 ADC 原始值在跳但保护消失。
  8. bt_armed=0 触发停车依赖下一次 50 ms 推帧：最坏 100 ms 急停延迟。
  9. EEPROM 写入与 FOC 16 kHz 中断竞争：FLASH 写期间关全局中断让 FOC 丢拍，关机瞬间可能听到电机异响。
  10. 优先级同级：DMA1_Ch1(FOC) 与 USART/DMA RX 均 Pre=0，STM32F1 同级不抢占；usart2_rx_check 长 memcpy 可能延误 FOC 中断响应。
  11. 信号板 CAN 中断 (Pre=2) 低于 UART (Pre=1)：BT+UWB+CAN 同时密集到达时 CAN 帧被挤掉，加剧 #11 的位图卡死。
  12. 变体宏冲突：main.c 中 SIDEBOARD_SERIAL_USART3 仍引用 Sideboard_R，与"USART3=FLW 接收"复用同一物理 USART；同时启用两个宏会让 DMA RX 缓冲被两个解析器同时消费。

⚠ 最应优先解决：UWB 段强制清零保护标志 + errCode + enable

位置：Src/main.c:334-351

flw_check_timeout();
timeoutFlgADC    = 0;
timeoutFlgSerial = 0;
timeoutFlgGen    = 0;
rtY_Left.z_errCode  = 0;
rtY_Right.z_errCode = 0;
enable = 1;
input1[inIdx].cmd = uart_steer_cmd;
input2[inIdx].cmd = uart_speed_cmd;

为什么优先

这是把整套软硬件分级保护体系（过流斩波、过温关机、FOC 错误、超时、看门狗式报警）集中拆除的一段代码，性质属于"所有安全网同时失效"。其它漏洞最坏只是某项保护失效；这里是一笔抹掉。

可能现象

  • 故障静默：错误蜂鸣 if (rtY_Left.z_errCode || rtY_Right.z_errCode) beepCount(1,24,1) 永远进不去；操作员不知道电机已经在报警。
  • 电机烧毁：FOC 检测到的堵转/相序错/霍尔故障/过流被即时擦除，enableFin 持续 true，PWM 一直打，电流超限直到 MOSFET/绕组热崩。
  • MOSFET 爆管 / 电池过放：当 bldc.c 硬件级斩波在中断未触发的瞬间未能立刻关断时，errCode 是软件最后一道线，已被拆除。
  • 超时类故障被掩盖：传感器/数据线断开 → 应当 timeoutFlg*=1，但被强制 enable=1 继续跑，目标丢失但车仍按上一帧命令运动。
  • flw_check_timeout 是唯一兜底：失帧 1 s 后才把 uart_*_cmd=0，期间车辆完全失控。
  • 二次故障级联：电机烧坏 → 霍尔信号异常 → FOC 仍被强制 enable → 进一步电流冲击 → 可能引燃电池/电线。

建议的最小修复

flw_check_timeout();
input1[inIdx].cmd = uart_steer_cmd;
input2[inIdx].cmd = uart_speed_cmd;
/* 不要再触碰 timeoutFlg* / z_errCode / enable */

enable 的初始置位仍走 main.c 上方的"初始小输入自动 enable"逻辑；FOC 错误码自然让蜂鸣器报警；超时仍生效。如果确实需要绕过 ADC 超时（因为没接油门刹车），应在 Input_Init 时把 inIdx 指向一个不会超时的虚拟输入源，而不是在主循环里每 5 ms 抹一次标志。
