信号板稳定性专题

决策层是否会卡死 · 信号是否打架 · 数据流是否清晰

一、数据流走向（每50ms一次）

输入源(异步中断)              主循环(轮询)              输出
─────────────                ──────────              ────
USART1 蓝牙  ──> bt_armed
USART2 BU04  ──> flw_*缓存 ──┐
                             ├─> 决策仲裁 ──> USART3 → 电机板
CAN1 TOF     ──> zone缓存 ───┘    (50ms周期)
★ 关键设计

三路输入完全独立、各管各，互不阻塞。主循环只读取共享缓存，不存在互锁条件。这是稳定性的最大优点。

二、决策优先级（实际代码顺序）

if (!bt_armed)            → 停车帧             [P1 最高]
else if (避障是闪避/围堵)  → 完全覆盖UWB        [P2]
else if (UWB在线)          → UWB跟随 + 减速融合 [P3]
else                       → 停车帧             [P4 兜底]
✓ 优点

互斥分支结构（if-else if），永远只走一条路径，不会出现"避障+UWB同时发"的冲突。决策不会打架。

三、卡死风险分析（逐项）

✓ 主循环不会卡死

主循环只有__WFI()等待中断 + 轮询缓存，无任何阻塞调用（除UART3发送50ms超时，下面单独说）。即使所有输入都掉线，仍会按50ms周期发送停车帧。

⚠ 卡死点1 · TOF 64像素位图

位置：tofsense_can.c s_rx_mask

问题：必须收齐64个像素才发布 s_zone_ready。若任意1帧CAN丢失，s_rx_mask 永远不会满，tofsense_get_zones() 永远返回false。

后果：避障决策冻结在丢帧前的最后一次 oa_result。如果当时是"无障碍"，后续即使真有障碍也不会触发；如果当时是"避障中"，会一直避障下去。

但：信号板主循环本身不卡死，仍按50ms发UWB跟随帧。

⚠ 卡死点2 · s_turn_flag 三面围堵

位置：tofsense_can.c 第200-212行

flag=0 → CCW, flag=1
flag=1 → CW,  flag=2
flag=2 → CW,  flag=2  ← 永远走else分支

实际行为：第一次CCW，之后永远CW，不是真正交替。

逃生条件：必须出现"非三面围堵"（哪怕一帧）才会重置flag=0。如果车彻底卡在三角死角，会一直朝同一方向打方向盘但出不去。

⚠ 阻塞风险 · UART3 发送

HAL_UART_Transmit(50ms timeout) 是阻塞调用。

正常情况下115200波特发30字节约2.6ms，没问题。但如果电机板USART3硬件故障或线断，每次发送会阻塞50ms。50ms内若有CAN/UWB中断仍能正常处理（中断优先），但主循环节拍会拖到50ms+，调试输出可能错过。

不会真卡死，但会降级。

四、信号"打架"风险分析

✓ 不会打架的场景
  • 避障 vs UWB跟随：if-else if 互斥，永远只发一帧
  • 蓝牙STOP vs 避障：bt_armed优先级最高，STOP直接覆盖一切
  • UWB超时 vs 避障：避障判断在前，UWB超时在后，避障期间不查UWB
⚠ 隐性冲突1 · UWB数据非原子读取

主循环这一段：

build_avoid_frame(frame, LINE_MAX, &oa_result,
                  flw_dist, flw_angle_x10);

读 flw_dist 后、读 flw_angle_x10 前，如果USART2中断进来更新了一帧，会拿到旧距离 + 新角度的混合数据。

影响：极偶然，发生概率约百万分之一量级（数据更新窗口几μs vs 50ms周期）。不严重。

⚠ 隐性冲突2 · SLOW_DOWN 与 UWB 角度

当TOF判定SLOW_DOWN时，dist被压到200cm（电机板算速度=（200-150）×3=150），但UWB角度仍照常×(-5)送出。

如果UWB此时正在大角度修正（比如目标偏左60°），车会边减速边打方向。这是设计意图，但若TOF误判减速，UWB转向命令会照执行，可能撞到侧面。

五、决策一致性问题

⚠ 避障决策表的"左优先偏置"
三区危险情况决策合理性
右+中 危险左闪✓ 合理
中+左 危险右闪✓ 合理
右+左 危险（中间空）左闪? 中间是通路，应直行
仅右 危险左闪✓ 合理
仅中 危险左闪? 仅中央障碍时左偏不合理（应看左右哪边空）
仅左 危险右闪✓ 合理

结论：决策表对"左+右"和"仅中"两种情况的处理偏简单，没有比较 FL/FR 哪边空隙大，固定左闪。在窄通道中可能反复撞墙。

六、最终结论

✓ 信号板基础架构是稳定的
  • 三路输入异步独立，主循环纯轮询，无死锁条件
  • 决策树是if-else互斥结构，不会信号打架
  • 有两层超时保护（BU04 500ms + 蓝牙门控）
⚠ 但有3个真实风险
  1. TOF 64像素卡帧：丢1帧CAN就冻结避障数据 → 加超时后按超时数据走
  2. s_turn_flag 不交替：三面围堵进入死角后只朝一个方向转 → 改用真正的CCW/CW交替
  3. 避障决策表左偏：仅中/左+右两种情况固定左闪 → 改成比较 FL/FR 选大的
✗ 与你反馈现象的对应
你的反馈信号板层面的解释
① 直线跑偏信号板放大角度×(-5)，与电机板30°死区组合后过冲
② 右转变左转信号板 angle = -uwb_angle_x10 * 5 取反是bug
③ 跑半路停BU04超时500ms或USART2 ORE错误后未恢复
④ STOP后再START卡住BU04重连UWB需要时间，期间持续500ms超时停车帧

七、改进优先级建议

  1. 立即修：去掉 angle = -uwb_angle_x10 * 5 中的负号 → 解决问题②
  2. 本周修：TOF 位图加100ms超时，超时后用上一帧zone继续判断
  3. 本周修：s_turn_flag改成 s_turn_flag = !s_turn_flag 真正交替
  4. 调参：减小 FLW_ANGLE_DEADZONE_DEG（从30→10）→ 解决问题①
  5. 可选：避障决策表改成"找最大空隙方向"
