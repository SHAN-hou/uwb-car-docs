避障+跟随 问题清单

按严重程度排列 · 全部位于信号板代码中

一、UWB跟随问题

致命P1 · 角度方向完全相反

位置：main.c:328

int angle = -uwb_angle_x10 * 5;  /* 取反×5 增益 */

现象：目标在右边，车向左跑，越跑越远

原因：负号把方向反了。UWB报+150(右偏15°) → 信号板输出-750 → 电机板算出左转

修复
int angle = uwb_angle_x10 * 5;   /* 去掉负号 */
严重P2 · UWB数据无滤波，跳变直接放大

位置：main.c:328 + flw_feed_byte()

现象：车行驶抖动/突然转向/走S形

原因：BU04 的 angle_x10 帧间跳变可达 ±50（5°），经×5放大后变成 ±250，占电机板量程的25%。无任何平滑。

示例：连续3帧UWB角度: 120, 170, 130 (正常波动±5°)
经×5后: 600, 850, 650 → 帧间跳250，电机板直接响应 → 车抖
修复方案

在 build_avoid_frame 前对 flw_angle_x10 做一阶低通滤波：

static int angle_filtered = 0;
angle_filtered = angle_filtered * 7/8 + uwb_angle_x10 * 1/8;
int angle = angle_filtered * 5;

也可用3点中值滤波消除尖刺后再乘增益。

严重P3 · UWB距离跳变导致急加急停

位置：build_avoid_frame() → dist = uwb_dist

现象：车突然加速然后急刹

原因：UWB dist偶尔跳变（遮挡/多径），如突然从300跳到600再回300。电机板 speed=(dist-150)×3，所以600→speed=1350(被限到MAX)，下帧300→speed=450，瞬间急刹。

修复方案

对 dist 做限幅+缓变：

static int dist_filtered = 0;
int delta = uwb_dist - dist_filtered;
if (delta > 50) delta = 50;      // 每帧最多追50cm
if (delta < -80) delta = -80;    // 刹车可以快一点
dist_filtered += delta;
中等P4 · ×5增益 + 电机板30°死区配合不当

位置：信号板 ×5 + 电机板 FLW_ANGLE_DEADZONE_DEG=30

现象：小角度不修正（跑偏），大角度过冲（画圈）

原因：信号板 ×5 后电机板 ÷10 → 有效增益=×0.5。电机板30°死区换算回原始UWB = 6°才开始修正。6°内完全不管 → 跑偏。一旦超过6°，乘以KP=4突然出力 → 过冲。

修复方案

方案A（推荐）：电机板 FLW_ANGLE_DEADZONE_DEG 改为 5°（只改一行 config.h）

方案B：信号板 ×5 增益改为 ×10，缩小有效死区

方案C：信号板自己做死区+P控制，发出的angle已经是最终steer值，电机板当纯执行器

中等P5 · UWB超时后恢复延迟

位置：main.c:421 (now - flw_last_ms) <= BU04_TIMEOUT_MS

现象：STOP再START后要等几秒才动

原因：BU04 重新建立跟踪需要时间（首帧延迟1-3秒），期间持续超时发停车帧。用户以为卡了。

修复方案

加一个"等待UWB"状态LED闪烁提示。或在bt_armed从0→1时主动发"QUERY"命令给BU04请求快速恢复。

二、TOF避障问题

致命P6 · 64像素位图无超时，丢1帧CAN永久冻结

位置：tofsense_can.c:50-95

s_rx_mask |= (1ULL << idx);
if (s_rx_mask == 0xFFFFFFFFFFFFFFFFULL) { ... }

现象：避障突然失灵，或车一直在"闪避"停不下来

原因：

  • 如果在"无障碍"时丢帧 → oa_result 冻结为 AVOID_NONE → 避障永久失效，直到下次64帧全收齐
  • 如果在"左闪"时丢帧 → oa_result 冻结为 SHIFT_LEFT → 车一直左转停不了
修复方案
// 在 parse_pixel 开头加超时检测:
static uint32_t last_pixel_ms = 0;
uint32_t now = HAL_GetTick();
if (now - last_pixel_ms > 100 && s_rx_mask != 0) {
    s_rx_mask = 0;  // 超过100ms没收齐，丢弃残帧重新开始
}
last_pixel_ms = now;
严重P7 · 避障决策表"左偏"不合理

位置：tofsense_can.c:200-254

情况当前决策问题
仅中区危险左闪如果右边空间更大应该右闪
左+右同时危险（中间通）左闪中间是通路，应该直行
修复方案
// 仅中区危险: 比较左右哪边远
} else if (m_danger) {
    if (FL > FR) {  // 左边空间大 → 左闪
        r.action = AVOID_SHIFT_LEFT; ...
    } else {        // 右边空间大 → 右闪
        r.action = AVOID_SHIFT_RIGHT; ...
    }
}
// 左+右同时危险但中间通: 直行减速
} else if (r_danger && l_danger) {
    r.action = AVOID_SLOW_DOWN;
    r.dist_cm = cfg->slow_dist;
}
严重P8 · s_turn_flag 围堵脱困不真正交替

位置：tofsense_can.c:202-212

if (s_turn_flag == 0) { CCW; s_turn_flag=1; }
else                   { CW;  s_turn_flag=2; }

现象：三面围堵时车只会先CCW一次，然后永远CW

原因：flag=2时 else 分支永远走CW，不会回到CCW。只有暂时脱离三面围堵(flag重置为0)才能恢复。

修复方案
if (s_turn_flag == 0) {
    r.action = AVOID_ROTATE_CCW; ...
    s_turn_flag = 1;
} else {
    r.action = AVOID_ROTATE_CW; ...
    s_turn_flag = 0;   // ← 改为0，真正交替
}
中等P9 · TOF数据无滤波，单点噪声触发避障

位置：tofsense_can.c:60-82 取三区最小距离

现象：偶尔无障碍物时车突然闪避一下

原因：每区16像素取最小值，如果有1个像素因噪声报了0.3m，整区就被判"危险"。没有最小连续帧数确认。

修复方案

A. 丢弃每区距离最小的2个点（去极值）再取min
B. 连续2帧都判"危险"才执行避障（加计数器）

中等P10 · 避障→跟随切换时无平滑过渡

位置：main.c:406-430 if-else分支

现象：避障结束后车突然转向回归UWB方向（甩头）

原因：上一帧 angle=±1100(避障)，下一帧直接切到 angle=UWB值(可能是200)，变化900+，电机板直接响应。

修复方案

记录上一帧发出的 angle/dist，当前帧做限幅过渡：

static int last_angle = 0, last_dist = 0;
int da = angle - last_angle;
if (da > 300) da = 300;    // 每帧最大变化300
if (da < -300) da = -300;
angle = last_angle + da;
last_angle = angle;

三、避障+跟随融合问题

严重P11 · SLOW_DOWN时保留UWB角度的风险

位置：main.c:339-342 build_avoid_frame()

case AVOID_SLOW_DOWN:
    if (dist > ar->dist_cm) dist = ar->dist_cm;
    break;  // angle 保持 UWB 的 -angle_x10*5

现象：前方有障碍物在减速，但UWB目标在侧面 → 车边减速边转弯 → 侧撞障碍物

修复方案

SLOW_DOWN时按距离比例衰减UWB角度：

case AVOID_SLOW_DOWN:
    if (dist > ar->dist_cm) dist = ar->dist_cm;
    // 越近障碍物，越削弱UWB转向（优先直行）
    float ratio = FM / cfg->slow_down_distance; // 0~1
    angle = (int)(angle * ratio);
    break;
中等P12 · 避障动作不考虑UWB目标方向

位置：tofsense_avoid_danger()

现象：UWB目标在左侧，左边有障碍 → 车右闪后继续追UWB又回来 → 反复左右摆

原因：避障决策完全不知道UWB目标在哪，纯看TOF三区。应该在避障方向选择时参考目标角度。

修复方案（进阶）

把 uwb_angle_x10 传入避障函数作为辅助参考。当左右都能闪时，优先闪向UWB目标方向：

// 仅中区危险 + UWB目标在右侧 → 优先右闪（闪完就能追目标）
if (m_danger && uwb_angle_x10 > 0) → SHIFT_RIGHT
if (m_danger && uwb_angle_x10 < 0) → SHIFT_LEFT

四、性能/可靠性问题

低P13 · ISR中调用 sscanf

位置：flw_feed_byte() 在USART2中断中执行

sscanf解析5个int约20-50μs，期间CAN中断被屏蔽（同优先级）。极端情况下可能丢CAN帧。

低P14 · parse_pixel中浮点运算

位置：tofsense_can.c:46 temp / 1000.0f 在CAN ISR中

C8T6无硬件FPU，软件浮点约3-5μs。64帧连续收时占CPU约320μs/批。
